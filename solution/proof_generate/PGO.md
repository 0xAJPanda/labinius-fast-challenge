# Profile-guided build

The Cargo compiler wrapper preserves every supplied compiler argument, including
`-C target-cpu=native`, and adds `-C profile-use` for crate compilation. Compiler
queries are passed through unchanged. The checked-in profile contains execution
counts, not witness data, commitments, proofs, or instance-specific results.
The final executable has no profiling instrumentation or runtime profile file.

Profile provenance:

- Prover source: `a3bbe0ff0647feefab475b0a7d8c6676e2542f40` (submission
  `b64d9cba-4bfb-462b-9521-51d60cd9a865`).
- Rust 1.99.1 (`58cf8f9c3`), LLVM 23.1.1, matching `llvm-profdata` from
  `llvm-tools-preview`.
- Intel Xeon Platinum 8488C, eight available logical CPUs, native CPU flags.
- Three sequential fresh 32-byte seeds and tables generated by the trusted
  table generator, with each instrumented proof checked by the unchanged
  verifier. Each proof used Q=35039150080 and occupied 13,958,612 bytes.
- IR-level profile: 1,447 functions, 16,209 blocks, merged with
  `llvm-profdata merge`. Profile size: 433,568 bytes.
- SHA-256: `cffee64aa3ef6a27d859b4856eea125618f3a7fe8ea326af4035ae636637e0a2`.

To regenerate, use a private staging copy of the same prover source. Change only
that copy's compiler wrapper to append `-C profile-generate=/work`, keeping the
other release flags unchanged. Compile offline through the supported build
sandbox. Run it through `run_contestant_prover` on three fresh trusted tables,
verify every proof, and retain the `.profraw` execution profiles from the ordinary
writable proof directory. Merge them using the matching `llvm-profdata`, then
replace this profile and return to the profile-use wrapper. Keep training tables,
proofs, raw profiles, and compiler output outside the submitted source payload.
Thread scheduling can change counter totals, so retraining need not reproduce
this profile byte for byte. This frozen profile makes the chosen build input
explicit and reviewable.

Training is not a scored benchmark. Validate every final candidate with the
unchanged five-fresh-seed Yukon harness. The profile affects compiler decisions;
it does not change transcript rules, the proof format, or verification checks.

References: [Rust PGO workflow](https://doc.rust-lang.org/rustc/profile-guided-optimization.html)
and [Cargo compiler wrappers](https://doc.rust-lang.org/cargo/reference/config.html#buildrustc-wrapper).
